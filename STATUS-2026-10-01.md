## 3. Bugs found and fixed during testing

These were found by testing, not by reading code. Three of them were **my own** or would have
silently corrupted data:

1. **Silent batch loss (data-loss).** The model always returns `calendarId: "cal_ai_batch"`, and
   the insert used `ON CONFLICT DO NOTHING` — so every batch after the first was discarded while
   the API still reported `persisted: true`. The DB kept the old coffee content while new image
   files overwrote the old ones in place. Fixed with a server-minted unique id per generation.
2. **`public/` is snapshotted at server start.** Images written after boot returned 404, because
   `next start` collects the public file list once. Generated media moved to `media/` (gitignored
   runtime data) and is streamed by `/api/media/[...path]`.
3. **Scheduler could never authenticate.** Middleware redirected `/api/scheduler` and `/api/media`
   to the login page. Both are now self-authenticating (own checks inside the route).
4. **Postgres type error.** Reusing `$1` in both `SET status = $1` and
   `CASE WHEN $1 = 'PUBLISHED'` → *"inconsistent types deduced for parameter $1"* (HTTP 500).
5. **`.gitignore` didn't actually cover media.** My first check matched `/tmp-media/` — a false
   positive. Verified again after fixing.
6. **`test_auth_matrix.js` certified the backdoor.** It asserted that `admin123` returns 200 and
   that the session is an unsigned cookie. Deleted and replaced (§6).

## 5. Blocked on you (cannot be done from here)

1. **Google sign-in** — `Error 400: redirect_uri_mismatch`. Add
   `http://localhost:3000/api/auth/callback/google` as an authorized redirect URI (and
   `http://localhost:3000` as a JS origin) in the Google Cloud OAuth client.
2. **Rotate the burned secrets.** `NEXTAUTH_SECRET`, the Postgres password, the Google client
   secret and the DeepSeek/OpenAI keys were hard-coded in source files (so they were almost
   certainly sent to a third-party model). They never entered git — the commit gate blocked it —
   but treat them as compromised.
3. **Platform credentials for real posting.** None are set (`LINKEDIN_CLIENT_ID/SECRET`,
   `TWITTER_CLIENT_ID/SECRET`, `INSTAGRAM_APP_ID/SECRET` are all absent), and Meta/X require app
   review before they will accept posts. Until then the honest outcome is `SKIPPED`.
4. **`SCHEDULER_SECRET`** — set it in `.env` if you want the headless tick (Task Scheduler) to
   authenticate without an admin session. Unset, the endpoint fails closed and requires an
   admin session.

## 7. Known limitations (stated plainly)

- **Live publishing: LinkedIn only, text-only.** Image upload needs LinkedIn's assets API and an
  approved app. X and Instagram live publishing are not implemented and say so.
- **Instagram identity** resolves the Facebook user; publishing needs the IG business account id,
  which is not wired yet.
- **Text inside generated images is unreliable** (a flowchart came back with "IND" instead of
  "NO"/"END"). Prompt-side mitigation, not fixed.
- **Two writers on one repo.** `start_server.js` was modified by something else again during this
  session, and a foreign process took port 3000 once. Antigravity should be paused while one of us
  edits, or the repo should be handed to one writer at a time.
- **`src/app/page.tsx` still has a display-only `INITIAL_USER` constant** (`usr_creator_01`) used
  as the default UI identity before the session loads. It no longer writes to the DB, but it should
  be replaced with the session user.
- **Costs:** image generation spends real money on your OpenAI key (~$0.01/image at `quality: low`).
  This session's tests generated 9 images.
